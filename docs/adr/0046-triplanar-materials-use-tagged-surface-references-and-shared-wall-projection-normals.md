# Triplanar materials use tagged surface references and shared wall projection normals

**Status:** Accepted

World surfaces previously named only Sub-material ids. Image-backed materials do not belong to a ProcMaterial Technique, and inferring a material family by searching multiple registries would make identifiers ambiguous. A floor, ceiling, or wall therefore owns a tagged Surface material reference whose kind is either `subMaterial` or `triplanar` and whose reference is respectively a stable Sub-material id or qualified Triplanar material resource name. The C++ property fields are `floorMaterial`, `ceilingMaterial`, and `wallMaterial`; constructing, assigning, comparing, or converting a Surface material reference as though it were a string is not supported. Existing scalar strings deserialize as `subMaterial` references, while subsequent serialization writes the tagged mapping. Existing one-argument Lua material methods remain explicit Sub-material shortcuts, with separate Surface-material methods exposing the tag. A World lists a referenced Triplanar material as its direct dependent resource; that resource owns its ImageResource dependency.

A Triplanar material is a file-authored resource containing one albedo ImageResource, a World-space tile width, and blend sharpness. It uses fixed engine-owned world programs rather than an asset-selected shader, requires repeat wrapping, preserves image aspect ratio, ignores alpha, and uses fixed non-metallic matte lighting (`metallic = 0`, `roughness = 0.7`). The image is sampled on fixed, unflipped, World-origin-anchored axis planes; absolute Projection-normal components provide the blend weights. It owns no further PBR maps or controls, Chip settings, or acoustic choice. Surface Embossing and wall normal-map overrides still compose with it, while authored wall-mask data remains dormant until the wall again uses a Sub-material.

Ordinary geometric normals cannot make an arbitrary two-dimensional image meet exactly across sharp wall corners: each wall would choose different triplanar weights. Rendering therefore derives a separate Projection normal that never affects lighting. Along every overlapping elevation span of an Arrangement-connected junction, all incident walls using the same Triplanar material receive one deterministic averaged Projection normal; a fixed World-axis direction is used if the average cancels. The direction interpolates across each wall span. Render geometry is split at adjoining floor and ceiling elevations as needed to isolate spans, without changing Arrangement topology, collision, picking, or authored geometry. Equal World position, elevation, projection coordinates, and Projection normal then guarantee identical albedo samples along the shared vertical edge at any wall angle. Floors and ceilings use their ordinary projection orientation and need not match walls exactly.

The editor presents loaded Triplanar materials as a read-only source in both material pickers, ordered and regex-filtered like Sub-materials. Their thumbnails use a three-face corner rendered through the real World pipeline; selected-resource details are read-only, while Embossing remains editable. The initial built-in `World/TriplanarFloorTiles` resource uses the existing `Floor5` image with tile width `32` and blend sharpness `4`.
